# 2.0.8 桌面变更与恢复卡顿修复

- 分支 test，基于 790e605；起始工作区干净，核对近期提交和文件历史，专用 SDK 与依赖已安装。只读确认现场运行 2.0.7，无主动 Windows 操作验证。
- 卡片删除原先在 UI 线程同步调用 Shell 回收站，可能阻塞所有卡片绘制和事件处理；改为独立 STA 线程，不降级为永久删除，保留系统错误/取消语义，操作期间共享工作区锁，退出保护不变。诊断记录删除开始/完成。
- 原桌面恢复仅监听外部事件，Win+D 在前台事件之后最小化卡片时可能错过快路径；新增仅本进程最小化开始监听，初次恢复排在输入优先级，后续约100ms检查，最多10次。保留3秒低频兜底、虚拟桌面遮蔽保护、不激活/不置顶卡片。记录实际修复状态。
- 桌面新增原先 default 收纳后逐张 LoadReferences 并重装 watcher、重建控件；改为仅调度 default 卡片差异同步，文件操作刷新也保留 watcher 和未变化控件。旧异步快照以版本号作废。
- 桌面事件合并等待约750ms，减少资源管理器连续创建/重命名时的扫描与写入；收纳仅操作分组配置，不打开文件内容、不改动真实文件。删除只更新受影响视图。
- 实际“桌面新建报错”缺少提示文字，已向用户询问发生于 Windows 桌面还是卡片新建；本版不能声称该错误已被复现或彻底解决。卡片内新建后的自动选中/滚动可能随异步差异刷新稍后出现，待验收。
- 版本 2.0.8；功能提交 1c4a89b、a0431a1、4958944。未运行测试、lint、独立类型检查、浏览器或 Windows 交互验收。
- 用户验收待进行：小文件/文件夹删除与取消、所有卡片是否保持可见、Win+D/显示桌面恢复、桌面右键新建并立即重命名、default 收纳、跨卡片转移后更新、全屏退出/虚拟桌面。Windows 自身合成动画仍可能短暂影响显示，不能保证完全无延迟。
