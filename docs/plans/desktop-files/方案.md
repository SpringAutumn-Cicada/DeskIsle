# 桌面文件模式与同名冲突方案（待确认）

## 目标与推荐决策

卡片由跨目录引用改为桌面文件分组。所有卡片可操作业务文件实际存在于Windows返回的DesktopDirectory根目录或普通子目录；不硬编码C盘/E盘，不为每张卡片自动建同名目录。配置仍在LocalAppData，不等于卡片文件。外部导入推荐复制、保留原件，卡片打开/删除/拖出上传均操作桌面副本。此举保证微信清理不影响已导入文件，又不破坏微信原存储。

同名文件：漂亮独立深色弹窗展示来源/目标路径、类型、大小和修改时间，提供覆盖、跳过、取消本次操作；默认跳过，默认不勾选对后续同类冲突应用。批量取消保留已完成项目，明确成功/跳过/失败/取消数量。同名文件夹推荐合并，保留目标独有内容；内部同名文件再询问。文件与文件夹类型不同不整项替换，提示跳过或改名。

## 入口行为

- 桌面已有项目拖进卡片：仅分组，不复制自己；卡片内左右排序不改文件位置。
- 微信/下载/其他位置的文件拖入卡片空白：后台复制到桌面根目录，成功后加入该卡片，失败不加入。文件夹递归导入到桌面同名文件夹，拒绝链接/目录联接及未下载云占位路径，避免引入外部目标和循环。
- 外部文件拖到卡片内文件夹中央：复制到该桌面内文件夹，不先复制根目录再移动；两侧仍表示加入分组/排序语义，外部不能冒充内部排序。
- 卡片内项目拖到桌面内文件夹中央：真实移动，与现有功能一致；新增统一覆盖/跳过。内部文件夹合并需要处理逐项成功及失败，不因部分完成删除整个源目录；失败项仍可恢复/重试。
- 新建文件夹/TXT/MD/DOCX/XLSX/PDF/PPTX固定到桌面根目录，删除更改位置按钮、目录选择器、CreationDirectory的生效逻辑。旧字段仅为读取兼容保留，不再作为目标。
- 删除操作为桌面真实文件回收，移出卡片仅解除分组。导入来源不会随桌面副本删除。
- 移除任意目录浏览和任意重新定位入口；保留打开所在位置。卡片菜单可增加打开桌面。桌面内子目录只由明确进入该文件夹的操作访问；若实现文件夹内部视图，其新建位置也必须是正在浏览的桌面内子目录，且界面标明。
- 文件拖出上传交付桌面实际路径；不再交付微信/下载原始路径。
- 导入临时文件、备份与进度不作为卡片内容。监控只关心桌面及当前分组涉及子目录，外部删除/重命名同步组内记录。

## 覆盖与失败处理

复制前检查磁盘空间/访问，后台准备完整临时副本后再提交，避免直接截断旧目标。覆盖须由本次冲突选择授权，并保留可恢复旧文件；替换失败不能先删目标。并发期间目标变化需再次询问。进度可取消，取消只清理应用拥有的暂存项，不动来源。跨盘导入是复制而非跨盘目录移动；目录合并逐项记录，不能宣称整批事务性成功。运行时操作记录包含目标及成功/失败结果，配置仅在实际文件成功落地后更新。

同一目标已有项目被覆盖时，各卡片引用同一路径，无需生成重复条目；跳过不更改目标，也不悄悄将未导入来源绑定到既有文件。用户可另拖目标文件进行分组。

## 历史数据迁移

首次升级检测旧外部引用，先备份配置，显示目录/项目数量和迁移清单，不在启动时静默执行批量复制。用户选择导入到桌面或暂不导入；暂未导入的引用进入独立待迁移提示，不作为正常可操作卡片项目。按引用父子关系建立映射，文件夹及其内部单独引用不能重复复制；仅成功项改为桌面路径并保存。旧来源和原配置备份保留，重复启动不重复导入。失效来源列为无法导入，允许移除分组，不造空文件。

## 实施顺序与验收

1. 统一桌面路径边界及数据模型，收口新建、定位、浏览和上传入口。
2. 导入服务与美化冲突框：复制/合并/覆盖/跳过/取消、进度、失败及恢复材料。
3. 接入拖入与内部移动、分组更新、历史迁移和监听。
4. 分功能本地提交，全部完成后集中构建、校验并复制一个最终包到实际桌面。不自动运行测试或Windows交互验收，除非用户明确要求。

验收重点：微信文件导入后路径在桌面、清理原件后副本可用；所有新建类型落桌面；同名覆盖/跳过及目录合并保留目标独有文件；取消不损伤原件/旧目标；旧配置迁移幂等；桌面重定向/长路径/多卡片；上传路径、排序和桌面隐藏不回退。使用临时目录及临时文件，不能拿真实业务文件做覆盖试验。
