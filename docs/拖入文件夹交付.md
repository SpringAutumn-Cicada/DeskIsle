# 0.6.0 拖入文件夹

## 交互

在同一卡片内拖动单个文件或文件夹：普通文件仍按左右半区排序；文件夹左右各20%区域保留绿色插入线，中央60%区域切换为蓝色边框/浅色底和“移入「目标」”，隐藏插入线。自身、子目录、已经位于目标目录等无效投放显示红色原因，不回落为排序。拖出上传继续携带标准FileDrop且仅允许Copy。

中央松手后，等OLE拖动结束再弹出独立深色440×360 DIP确认框（屏幕小则限制最大尺寸），列出源路径、目标文件夹和可编辑目标名称；取消为默认按钮。点击移入后检查名称、路径、同名与权限；冲突保留弹窗可改名。确认通过后后台重新检查并执行真实移动。当前收藏卡片移除原项；其他卡片中同路径及目录后代引用、排序路径、浏览位置和创建目录同步更新并保存。目录视图刷新后自然不再显示移走项目。

## 文件安全与边界

- 不覆盖、不合并；文件使用File.Move(overwrite:false)，目录使用Directory.Move。确认预检与实际操作前各检查一次。
- 拒绝根目录、自身、自己的子目录、已经在目标文件夹的投放；拒绝源/目标及其祖先中的符号链接、目录联接和其他reparse路径（包括部分云占位文件）。
- 跨盘目录不递归复制删除，明确提示改用资源管理器；跨盘文件使用系统文件移动API，可能耗时。没有移动进度百分比或中途取消，操作期间保留状态提示、禁止关闭和冲突文件操作。
- 同一时刻只允许一个内部移动；其他卡片已有创建/删除/模态弹窗或拖动时拒绝开始。移动期间暂停文件同步应用，结束后补偿刷新。
- 失败保留原引用，提示检查源与目标；跨盘移动不承诺事务性，异常时可能需人工检查两处。不自动删除错误产生的目标，不尝试反向移动。
- 文件成功但配置写入失败时明确报告真实目标路径，内存引用已更新；不会因保存失败将文件反向移动。旧配置备份保留，需修复权限后保存。
- 首版只处理同一卡片单项内部拖动，不提供多选、跨卡片移动或外部文件投进文件夹；外部拖入仍是添加引用。
