# 1.10.0 通用后台恢复机制

分支 test，基于 5d4977e。恢复中断工作时保留三个已有未提交文件；相关修改均属于本任务。项目专用 SDK 已安装。未修改全局配置。

## 第一阶段：统一恢复与脱敏诊断

移除仅限微信的判断，图标与隐藏预览共用运行进程核对、可见窗口恢复、后台托盘恢复路径。每次点击刷新可见窗口快照，按完整可执行路径匹配进程；权限无法确认时不启动新实例。仅进程未运行时允许普通启动，右键打开新窗口属于主动启动。

托盘扫描只在已知通知区域/溢出容器内进行。目标按当前进程 PID 和应用文件产品信息评分；Explorer 拥有的 UIA 控件 PID 不代表目标应用。只有唯一明确 PID 归属自动调用；名称匹配仅用于候选排序，不作为自动归属依据。无法确认时由用户选择真实托盘项目，再重新定位，拒绝歧义项目。控件优先 InvokePattern，缺失时才尝试校验命中目标的真实鼠标操作。未知系统结构仍可能没有可访问候选，不猜测私有回调。

恢复只有检测到同路径主窗口可见、启用且目标进程获得前台才记为成功。发送动作、点击成功不等于恢复成功。已运行应用不通过重新启动恢复，不强制显示内部隐藏窗口。

诊断保存在 `%LOCALAPPDATA%\DeskIsle\restore-diagnostics\last-restore.json`，应用右键可打开目录。记录版本、OS、失败阶段、PID、托盘控件类型信息及名称/标识散列，不写聊天内容、窗口标题、托盘提示原文、完整路径或认证材料。只有一个有界的最新记录，不进入 Git。

自动操作、用户选择、任务栏临时访问均保持取消与退出清理。诊断/候选选择不是独立后台应用面板。系统语言、Explorer 结构、应用权限及无托盘应用仍存在兼容性边界；不声称所有第三方应用已通过。

开发验证：人工源码审阅。按用户规则未运行测试、lint、独立类型检查或 Windows 交互验收。最终自动发布仅验证可发布性、ZIP 完整性与桌面复制散列，由用户验收微信、QQ、钉钉、多实例、权限差异、Explorer 重启及反复关闭恢复。

## 第二阶段：确认关联与交互收尾

第一阶段提交 e702251。用户选择只有在恢复主窗口并观察到目标进程获得前台后才记入内存，限定当前路径和进程集合，不持久化用户配置。关联失败或进程集合变化重新确认，目标缺失不退回名称猜测。取消/退出关闭选择窗，观察最多二十轮。多窗口图标优先激活可见启用窗口，不因陈旧隐藏句柄误走最小化。

在 Windows 常见 Explorer 托盘中 UIA 无法公开提供第三方应用 PID，此时首次恢复需要用户确认目标；这不是自动识别已经解决。若系统不暴露任何候选，则记录 no-accessible-tray-items，后续需依据该机器诊断补充容器适配，不重新启动进程掩盖问题。
