# 2.0.15 无布局写入预览修复

- 分支 test，基于 846088f；开始前工作区干净，已核对项目约定、近期提交、相关文件历史，项目 SDK 与恢复依赖存在。
- 移除 WindowPeek 对源 HWND 的 SetWindowPlacement、ShowWindow、SetWindowPos 操作，以及依赖固定750ms的缓存保护。悬停不再修改真实窗口位置、大小、最小化状态、置顶属性，也不再发出需要回退的异步布局请求。
- 使用独立无激活、不进任务栏的 HwndSource+DWM 缩略图画面层，在真实窗口当前矩形或最小化前记录的矩形显示全尺寸内容。全部组合成员注册成功后统一显示；失败则销毁画面层，保留普通缩略图。
- 画面层不作为预览面板的 owned popup，避免覆盖 owner 后无法重新将预览面板置于其上；预览和关闭控件保持在画面层上方。
- 移开、切换、关闭、翻页或前台改变仅销毁本地画面层；点击缩略图或全尺寸画面才进入既有单窗激活/组合打开路径。过期画面点击回调检查当前候选会话后再执行。
- 最小化窗口由 DWM 提供画面，可能是缓存帧；这是视觉查看，不保证最小化应用实时更新内容。首次看到时已经最小化且没有实际布局记录的窗口仍使用系统还原位置。原生 Snap 组的内部元数据恢复不由画面层实现。
- 未运行测试、lint、独立类型检查或 Windows 交互验收。用户待验收：组合悬停前后实际位置不变、快速组合/单窗切换、移开清理、点击打开、顶层控件、多屏不同缩放、最小化缓存画面表现。
