# 2.0.14 组合预览位置修复

- 分支 test，基于 d6e77e9，工作区原本干净；已核对近期提交、WindowPeek/SplitGroups 历史、项目规则与已安装的项目 SDK/恢复依赖。
- 上一版仅还原 WINDOWPLACEMENT，未区分贴靠前的普通还原矩形与实际分屏矩形，组合临时展开仍可能位置不符。
- 复用 SplitGroups 最小化前记录的 GetWindowRect 实际屏幕坐标，原最小化且非最大化窗口临时展示时按此矩形构造独立 display placement；不改写会话保存的原始 placement。
- 根据所在显示器工作区和屏幕原点差值转换 WINDOWPLACEMENT 工作区坐标，工具窗口保留屏幕坐标；转换信息读取失败则跳过本次临时展开。
- 正式点击保持实际分屏矩形，不再写回贴靠前矩形；移开仍按原始 placement 最小化。原已打开窗口仅调整层级，原最大化恢复规则保留。
- 临时会话结束后保护布局缓存 750ms，防止异步还原未完成时，把中间窗口位置误当成用户新布局；保护不延迟窗口展示/最小化请求。
- 参考：[IsWindowArranged](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-iswindowarranged)、[WINDOWPLACEMENT 坐标规则](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement)。
- 开发侧仅代码审阅及授权发布。未运行测试、lint、独立类型检查、浏览器或 Windows 交互验收。
- 用户验收待进行：两窗均最小化、一窗最小化、组合与单窗交叉悬停、快速移开再进入、点击组合正式打开、多屏及顶部/左侧任务栏。首次观察前已经最小化的窗口缺少实际布局缓存，仍回退系统还原位置；应用线程长时间无响应可能超过缓存保护期，不能以包校验代替交互验收。
