# 0.4.4 全屏/最大化退出后的卡片恢复

## 运行状态取证

用户重新启动0.4.3并复现后，只读枚举窗口：进程存在且响应；三张DeskIsle卡片的窗口均存在、WS_VISIBLE为真、未最小化、父窗口为0，确认均为普通浮动降级模式。它们在顶层窗口Z序位置分散。MainWindowHandle为0不能据此判断窗口消失，因为卡片不显示任务栏按钮。

这份快照不能完整还原此前全屏切换瞬间，也不能单独断定具体哪张卡片曾被遮挡。代码确认的缺陷是：原恢复计时器仅在请求桌面模式且父窗口失效时处理，浮动降级模式完全跳过；也没有前台切换或返回桌面事件处理，窗口仍存在时不会请求重绘或纠正桌面层级。

本轮诊断只读，没有关闭、显示、移动或注入用户当前的0.4.3窗口；修复需退出旧版、运行新包后生效。

## 修复

- 全应用共用一组OUTOFCONTEXT WinEvent Hook，监听前台切换、最小化结束、桌面切换及Explorer桌面层级变化；本机回调短小，通过WPF Dispatcher合并事件，并做一次350ms过渡完成后的有限重试。不注入Explorer。
- 只有前台确认为Explorer的桌面窗口时才恢复卡片；普通应用处于前台时不拉高卡片、不改变焦点、不覆盖应用。浮动模式将卡片放到Explorer桌面窗口之上、其他普通窗口之下，不设为Topmost。
- 检查原生显示/最小化状态，必要时以不激活方式显示；请求异步重绘。桌面嵌入模式检查父窗口关系，宿主不可用时安全降级，不强行显示隐藏的Explorer宿主。
- 尊重窗口显式隐藏、关闭状态和DWM虚拟桌面cloaking，避免复活已关闭卡片或将其他虚拟桌面的卡片拉回来。退出释放事件Hook与计时器。
- 保留原3秒检查作为事件挂钩失败时的兜底，并让浮动模式也参与返回桌面的恢复。

## 验证边界

本轮只执行只读运行状态诊断与交付所需构建、发布、包完整性/复制哈希校验，未运行自动测试、未主动切换或关闭用户应用做Windows交互验证。官方事件参考：https://learn.microsoft.com/en-us/windows/win32/winauto/event-constants 。

待用户验收：普通最大化窗口关闭/最小化、F11或游戏全屏退出后桌面卡片是否及时出现；其他普通应用仍能覆盖卡片；焦点不被抢走；Win+D、重复切换、多卡片、菜单操作和虚拟桌面切换正常；退出后无残留事件监听。独占全屏的DWM恢复时延和Explorer内部桌面层级兼容性仍需实测，不保证所有全屏实现时延一致。
