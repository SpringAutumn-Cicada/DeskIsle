# 2.0.10 系统应用图标修复

- test 分支，基于 16798f1；起始工作区干净，检查 Git 近期提交与图标相关历史，专用 SDK 与依赖已安装。
- 旧流程优先取 EXE 图标，磁盘管理为 mmc.exe 宿主而非管理单元本身，容易显示通用图标；系统设置的 EXE/Shell 图标也可能不可用或不正确。
- 只读核对现场：Windows ImmersiveControlPanel/Images 提供 logo.targetsize-256_altform-unplated.png 等；diskmgmt.msc 的 VisualAttributes/Icon 指向 %systemroot%/system32/dmdskres.dll、索引0。不修改系统资源。
- 系统设置优先使用安装目录原生高分辨率图标，读取失败继续尝试其他原生尺寸及既有回退；使用 OnLoad 解码并释放文件流、冻结图片，无长期文件占用。
- 磁盘管理（中文/英文窗口标题且为 MMC）读取本机 diskmgmt.msc 指定图标资源，按当前尺寸提取；其他 MMC 窗口优先 WM_GETICON/窗口类图标，不再优先宿主 EXE。维持原有 MMC 应用分组行为。
- 设置与 MMC 的运行窗口/固定快捷方式均检查真实执行程序。宿主窗口图标缓存额外包含窗口句柄与标题，避免不同管理窗口共用一个 EXE 缓存；窗口关闭/重开时重新取图。
- 应用路径增加 QueryFullProcessImageName + 查询有限信息权限读取，提高部分系统/提权进程识别成功率；保留旧路径读取回退，不提权。
- 使用窗口 DPI 请求 WM_GETICON 大图标，保留小图标回退；原有高质量缩放、后台限流与暂时失败保留上次有效图标不变。资源不存在或权限失败仍可能退回窗口原图，小图资源无法保证与原生高清图同样清晰。
- 版本 2.0.10。开发侧仅代码审阅和只读系统资源核对，未运行测试、lint、独立类型检查、浏览器或 Windows 图标交互验收。待用户验收：设置运行图标/固定入口、磁盘管理、其他 MMC、多个宿主窗口、高 DPI、开关窗口与缓存更新。

依据：[WM_GETICON](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-geticon)、[IShellItemImageFactory::GetImage](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage)。
